## What I understood
I understood that an index helps Oracle find data faster, like the index at the end of a book. Instead of reading every row in a table, Oracle can use the index to jump closer to the rows it needs. But an index is not always useful. If the query returns too many rows, Oracle may choose a full table scan because reading the whole table can be faster.

I also understood that cardinality is important when deciding if an index is useful. A column with low cardinality has only a few different values, like 'site_id' with values from 1 to 5 or 'status' with only three possible values. These columns are not always good for indexes because each value appears many times. A column with high cardinality, like patient_id, is usually better because it helps Oracle find a smaller group of rows.

I understood that date indexes can help, but it depends on the size of the date range. If I search only the last 7 days, Oracle may use the index because the query returns fewer rows. If I search the last 700 days, Oracle may ignore the index and scan the whole table because the query returns a large part of the table. This means Oracle chooses the plan that it thinks is cheaper.

Finally, I understood that using a function on an indexed column can stop Oracle from using the normal index.
