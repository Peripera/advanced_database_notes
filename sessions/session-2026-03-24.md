## What I understood
- I understood that a trigger is code that the database runs automatically when something happens in a table, such as an **INSERT, UPDATE, or DELETE**.
- Before this activity, I only had a basic idea of triggers, but now I understand that they can be used to check or change data before the database accepts the operation.
- In this activity, the insert trigger fills in the date and user automatically, the update trigger checks if the user is allowed to modify the row, and the delete trigger only allows the manager to delete records.
- I also understood that **:NEW** is used for the new values of a row, while **:OLD** is used to check the values that were already stored before the operation.

## What is still confusing
- It is still a little confusing when it is better to use a trigger instead of handling the rule directly in the application code.
- I also need more practice understanding when to use BEFORE, AFTER, and INSTEAD OF triggers.
