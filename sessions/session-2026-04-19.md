## What I understood

A KPI needs a clear rule, so everyone knows what the number means. In this activity, SQL does the hard work: it filters rows, joins tables, counts tasks, and calculates time. And Python can show the result, but the trusted answer is in the SQL query.  A good KPI says what question it answers, what rows it counts, what rows it ignores, what unit it uses, and what could make the number unfair.

The Colab helped show the same idea in a visual way. SQL calculates the numbers first. Then pandas and Plotly only display them as charts.
